# UI表示確認規約

UIを実装・変更した場合は、**必ず playwright-cli で実際の表示を確認**してから完了とすること。

## 手順

1. 開発サーバーを起動する(`pnpm dev`。ポート 14000)
2. playwright-cli で対象ページを開き、スクリーンショットを取得する
3. スクリーンショットを目視確認し、以下をチェックする:
   - レイアウト崩れ・要素の重なり・はみ出しがないこと
   - 実装した機能の表示が仕様通りであること
   - 操作後の状態変化(クリック・入力後)も同様に確認すること
4. 確認したスクリーンショットの取得コマンドと確認結果を作業ログに残すこと

## ルール

- 「コードを書いた・テストが通った」だけではUI実装の完了とみなさない
- 静的な初期表示だけでなく、主要なユーザー操作フロー(要素の追加 → 編集 → 結果の反映など)を通しで確認すること
- キーボード操作は実際のフォーカス先へ連続入力して確認すること。削除・undo でフォーカス中の要素が消えた後も操作を継続でき、別画面のフォーカスを奪わないことを確認する。テストで毎回ツールバーへキーを直接送ってフォーカス喪失を隠さない
- ビューポートはデスクトップ(1280x720 以上)を基準とする

- 接続ドラッグは終点も四辺中央へ固定し、近接候補の強調表示と確定先を一致させる。空白へのドロップ・取消後に発生するclick/dblclickまで通して、付箋が誤配置されず、次の通常クリックでも配置されず、種別を選び直した場合だけ配置できることを確認する。

- 通常の空白クリックは選択解除のみとし、付箋種別を明示的に選んだ後の1回だけ配置する。配置後・選択ツールへの切替後・Esc取消後に、空白クリックで付箋が増えないことを確認する。接続時は両要素の四辺中央から最短の端点ペアを自動選択する。接続済み付箋の移動・サイズ変更中にも両端を最短の辺中央へ付け直し、確定・取消・undo/redoで付箋と接続位置が一緒に更新されることを確認する。

- 付箋パレットは左サイドバーへ置き、クリックで1個の配置待ち、ドラッグ＆ドロップで直接配置できるようにする。配置待ちはカーソル位置にプレビューを表示し、既存要素の選択・移動・接続操作へ移ると解除する。ズーム・パン後のプレビューと確定位置の一致、パレット外へのドロップとEsc取消後の誤配置防止を確認する。
- HTML5のパレットドラッグを使うウィンドウではWindowsのWebViewにもイベントが届くよう `dragDropEnabled: false` を指定する。外部ファイルのドロップとパレットの配置操作を混同しない。
- クリック配置とパレットからのドラッグ配置はカーソルを付箋の中心に合わせる。プレビューと確定後の中心が一致し、種別ごとのサイズとズーム・パンを反映することを確認する。
- 背面の付箋を選択して実ポインターでドラッグし、最前面化しても捕捉が維持され、離した位置が保存・undo/redoへ反映されることを確認する。前後関係は付箋レイヤー内のz-indexで表し、ドラッグ中にDOM順を入れ替えない。選択枠・接続候補枠の線の中心と菱形の中心を一致させる。
- 通常の左クリックは押下位置から4px動くまでパンを開始しない。配置待ちで1〜3pxの手ぶれを含むクリックが1個配置になり、4px以上のドラッグでは配置せず、次のクリックで配置できることを実ポインター操作で確認する。閾値はズームによらない画面座標で測る。

- 付箋移動・リサイズ中の捕捉喪失だけでは位置を巻き戻さず、最後に表示した位置を1回だけ確定する。pointercancelは取消とし、pointerup後のlostpointercaptureで二重確定しないことを確認する。

- キャンバスの右プロパティは常時表示し、本文を直接編集する。入力中に付箋へフォーカスを奪わず、下書き保存・フォーカス移動による確定・undo/redoを検証する。専用の履歴・接続バーは表示せず、履歴はショートカット、接続は菱形ハンドルから操作する。
