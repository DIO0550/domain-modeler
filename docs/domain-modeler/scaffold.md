# scaffold — キャンバスからのドメインモデル生成

| 項目 | 内容 |
| --- | --- |
| 対象 | `.dcanvas` → `.dmodel` の一方向スキャフォールド生成 |
| 分類 | BE(変換ロジック) |
| ステータス | Draft |
| 関連文書 | canvas-format.md / model-format.md / model-editor.md(スタブ表現)/ app-shell.md(起動・保存ダイアログ) |

---

## 1. 位置づけ

- キャンバス(発散)で出した付箋を、ドメインモデルDSL(収束)の書き出しの土台に変換する
- **一方向・一度きり**。生成した `.dmodel` は以後手で育てる。再生成・差分マージ・逆方向の同期は行わない
- 出力は新規 `.dmodel` として保存ダイアログで書き出す(既存ファイルへの追記・上書きはしない)
- 生成物は「完成したモデル」ではなく「TODOだらけの叩き台」であることを明確にする。未定義参照の警告(model-core)が、そのまま続きの作業リストになる

## 2. 変換の入力と前提

- 入力はキャンバス文書全体(付箋と接続)
- 付箋テキストを識別子として使う。名前ベースであり、キャンバスのIDは持ち込まない(canvas-format 9 のとおり相互参照なし)

### 2.1 識別子化の規則

| 付箋テキスト | 扱い |
| --- | --- |
| 空白・改行を含む | アンダースコアに置換して識別子化する |
| 空文字 | 変換対象外(レポートに載せる) |
| 予約語と一致 | 末尾にアンダースコアを付ける |
| 同一テキストの付箋が複数 | 1つの識別子に統合する(同じ概念が複数箇所に貼られている状態とみなす) |

## 3. 種別ごとの変換規則

| 付箋種別 | 変換 |
| --- | --- |
| Domain Event | `data` スタブ(5.1 の形式) |
| Aggregate | `data` スタブ |
| Read Model | `data` スタブ |
| Command | `workflow` 宣言(3.1) + input用の `data` スタブ |
| Policy | `workflow` 宣言(3.2) |
| Actor | 変換対象外(型ではなく人。レポートに載せる) |
| External System | 変換対象外(自分たちのモデルの外。レポートに載せる) |
| Hotspot | `// TODO(hotspot): <テキスト>` のコメント行として出力する |

### 3.1 Command → workflow

Commandの付箋1枚が workflow 1つになる:

- 名前: 付箋テキスト(動詞句のまま)
- `input:`: `<名前>コマンド` という識別子を参照し、同名の `data` スタブを併せて生成する(workflowと同一名前空間での名前衝突を避けるための接尾辞)
- `output:`: そのCommandから接続線が出ている先の Domain Event を `OR` で連結する。接続先が1つもなければ `TODO結果イベント` を参照する(未定義警告として残る)
- **接続ラベルの反映**: ラベル付きの接続が1つでもあれば output は1項1行(継続行)とし、各項の行末にラベルをコメントで添える(`注文保留イベント // 在庫不足`)。すべてラベルなしなら1行に `OR` 連結する
- `error:`: 生成しない(手で足す)

Command以外の種別へ向かう接続(例: Command → External System)は output に含めず、workflow直前のコメントとして残す。

### 3.2 Policy → workflow

Policyは「Event が起きたら反応する」規則であり、Event をトリガーとする workflow として生成する:

- 名前: 付箋テキスト
- `input:`: そのPolicyへ接続線が入ってくる元の Domain Event を参照する。複数あれば `AND` で連結する。1つもなければ `TODOトリガーイベント` を参照する(未定義警告として残る)。ラベル付き接続は output と同じ規則で行末コメントに反映する
- `output:`: `TODO結果イベント` を参照する。接続先の Command をさらにたどって結果を推測することはしない(2ホップの推測は誤りやすいため、接続先Commandは直前のコメント `// -> <Commandテキスト>` として残す)
- `error:`: 生成しない
- Commandと異なり、input用の data スタブは生成しない(トリガーは既存Eventの参照で足りる)

## 4. 出力の構成

```
// <元キャンバスのタイトル> から生成 (<生成日>)
// このファイルは叩き台です。TODO と未定義の警告を埋めて育ててください

// ---- data ----

(Event / Aggregate / Read Model / コマンドdata のスタブ群)

// ---- workflow ----

(Command / Policy 由来の workflow 群)

// ---- 未変換 ----

// actor: 顧客
// externalSystem: 決済サービス
```

- 各群の並びは付箋の配列順(作成順)とする
- 変換対象外の付箋・空文字の付箋は末尾に「未変換」コメントとして列挙し、情報を落とさない

## 5. スタブの形式

model-editor 6 のスタブ生成と同一形式に揃える:

```
data 注文が確定した = string // TODO 詳細化
```

## 6. 生成の起動と確認

- キャンバス画面のメニューから起動する
- 保存ダイアログの前に、生成内容(テキスト全文)の確認画面を表示する。確認画面は読み取り専用とし、そこでの編集はさせない(編集は生成後に model-editor で行う)。確定で保存ダイアログへ、キャンセルで何もしない
- 生成完了後、生成したファイルを新しいタブで開く

## 7. スコープ外

- 再生成・差分反映(キャンバスの更新をモデルへ追い付かせる操作)
- `.dmodel` → キャンバスの逆変換
- workflow に変換されない接続のラベルの反映(Event 間の接続等。変換対象の接続のみラベルをコメント化する)
- レイアウト情報(座標・サイズ)の反映(出力順は配列順であり、位置は使わない)
