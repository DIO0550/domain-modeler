# モデル依存図 — 文書同期・統合仕様（FE）

機能: [概要](./index.md) / 状態: レビュー用ドラフト

## 基本原則

`.dmodel` の本文を唯一の正とする。解析結果・グラフ・配置は派生情報であり、図の表示操作で本文に新しい宣言・コメント・座標を追記しない。

既存の文書読み書き、外部変更取り込み、Undo/Redoの経路に接続する。独立した保存処理や履歴を依存図に持たせない。

## 表示の階層

| 階層 | 選択肢 | 保存先 |
| --- | --- | --- |
| 文書モード | モデル／ステートマシン | 既存仕様に従う |
| モデルの表示方法 | 定義＋プレビュー／依存図 | 開いている文書タブの表示状態 |
| 依存図の表示範囲 | 全体／関連のみ | 開いている文書タブの表示状態 |

新規オープン時のモデル表示は既存の「定義＋プレビュー」を既定とする。依存図を選んだ後にステートマシンへ移動し、モデルへ戻った場合は、同じタブ内で最後に選んだ表示方法に戻る。

## 保持する状態

| 状態 | 同一タブでの切替 | 文書を閉じて再度開く |
| --- | --- | --- |
| モデルの表示方法 | 保持 | 既定に戻す |
| 選択対象 | 対象を識別できる限り保持 | 未選択 |
| 全体／関連のみ | 選択が有効なら保持 | 全体 |
| パン・ズーム | 保持 | 初回配置へフィット |
| ノード配置 | 構造・寸法が変わらなければ保持 | 再生成 |

表示状態を `.dmodel`・sidecar・新規DBへ保存しない。別文書のタブに状態を混在させない。

## 本文更新時の反映

| 更新原因 | 依存図の動作 |
| --- | --- |
| 定義エディタで編集 | 既存の解析結果更新に追従して再生成 |
| 既存のリネーム・スタブ生成 | 同じ本文更新経路で再生成 |
| Undo/Redo | 復元された本文に対応する図へ更新 |
| AI・外部エディタがファイルを変更 | 既存文書管理が採用した本文から再生成 |
| 保存・再読込 | 読み込んだ本文から生成。座標の復元は行わない |

外部変更の採用・競合・IME中の遅延は既存の文書管理に委ねる。不正な外部変更を採用せず最後の正常表示を維持する場合は、図もその採用済みリビジョンを維持する。依存図だけでファイルを再読込したり、後勝ち方針を変更したりしない。誰が編集したかは表示しない。

## 選択とソース位置の整合

- グラフ、診断、ソース範囲を同一本文リビジョンの組として扱う。
- 古い位置情報を使って新しい本文を編集・選択しない。
- 非同期の配置結果が返った場合、現在の文書・リビジョンと一致するものだけを採用する。
- 本文更新後、一意な宣言名と種類で同じ対象を識別できれば選択を維持する。
- 重複名の編集、名前変更、削除などで同一性を確定できなければ選択を解除する。行番号だけで別宣言へ選択を引き継がない。
- 未定義ノードが定義済みに変わり、名前で一意に対応できる場合は定義済みノードへ選択を引き継ぐ。
- 選択解除時は関連のみ表示を終了し、全体表示に戻す。

## 配置更新方針

- 初回表示、対象宣言・参照の追加削除、ノード寸法の変化では配置を再計算する。
- 同じ構造・寸法の再解析では位置を維持し、毎回配置し直さない。
- 本文更新による再配置ではユーザーのパン・ズームを原則維持し、自動で毎回全体へフィットしない。
- 選択対象が表示範囲外になった場合は、その対象を見える位置へ移す。対象が消えた場合は選択を解除する。
- 関連のみ表示の選択変更、初回表示、「全体に合わせる」「再配置」では[画面仕様](./dependency-view-spec.md)のフィット規則を適用する。
- 配置中は直前の図を更新中として表示してもよいが、古いソース位置への移動操作は無効にする。
- 図の生成失敗を本文のエラーと混同しない。編集画面に戻れる状態を維持する。

## 責務の分担

| 担当 | 責務 |
| --- | --- |
| 既存model-core | 構文解析、参照解決、診断、ソース位置 |
| グラフ導出処理 | ノード・参照・描画用の辺・直接近傍の生成 |
| 配置処理 | 寸法と接続を受け取り、座標と経路を生成 |
| 文書・表示状態の管理 | 同じ文書リビジョンの管理、選択、切替、更新時の調停 |
| UI部品 | ツールバー、図、ノード、インスペクターの描画と操作通知 |
| 既存ファイルI/O | 保存、監視、外部変更の採用 |

UIコンポーネント内に解析・グラフ生成・更新制御を集中させない。表示部品と状態管理・純粋な導出処理を分ける。ファイル配置やAPI名は実装計画で既存コードを確認して決める。

## 既存仕様の変更点

| 既存仕様 | 現在の記載 | 本機能で必要な更新 |
| --- | --- | --- |
| model-editor §2 | エディタとプレビューは常に両方表示 | 定義＋プレビュー表示では維持し、依存図表示を追加 |
| model-editor §4 | 宣言カードを出現順に縦置き | 現行プレビューを維持し、別表示として依存図を追加 |
| model-editor §6 | カードからジャンプ等の編集支援 | 図から既存の定義編集へ移動する入口を追加 |
| model-editor §7 | AI・外部エディタの変更取り込み | 採用された本文の更新先に依存図を追加 |
| model-core | AST・参照解決・診断を公開 | グラフ導出に必要な入力と境界を整備。既存文法を変更しない |
| model-format | 自己完結したテキスト形式 | 変更なし。座標や表示状態を追加しない |

本書は追加機能の提案である。本PRでは既存仕様から提案への導線を追加する。既存画面の動作を変更する実装は後続Issueで扱う。

## 検証方針

コアの振る舞いは実際のDSL解析から生成するテストで確認する。画面と文書の同期は既存の文書・解析・履歴経路を通す結合テストで確認する。OSの実ファイル監視とトラックパッド操作はTauriで確認する。

座標の完全一致やコンポーネント内部の呼出回数ではなく、見えるノード・関係・移動先・本文不変性を検証する。

## 受入条件

| ID | シナリオ | 期待結果 |
| --- | --- | --- |
| SYNC-01 | 表示方法を繰り返し切替 | 本文が一致し、保存対象に表示状態が混ざらない |
| SYNC-02 | モデル→ステートマシン→モデル | 同じタブのモデル表示方法が復帰 |
| SYNC-03 | 依存先の追加・削除後に図を見る | 最新本文のノードと線を表示 |
| SYNC-04 | 編集をUndo/Redo | それぞれの本文に対応する図に更新 |
| SYNC-05 | 外部変更を採用 | 古い解析結果や配置結果が最新表示を上書きしない |
| SYNC-06 | 選択宣言を削除・識別不能に変更 | 選択解除、全体表示へ復帰 |
| SYNC-07 | 未定義の名前を定義 | 補助ノードが定義ノードへ置き換わる |
| SYNC-08 | 本文先頭に行を追加して定義へ移動 | 最新の正しい宣言位置へ移動 |
| SYNC-09 | 異なる文書タブへ切替 | ノード・選択・詳細が他文書に混在しない |
| SYNC-10 | 図を閲覧後に保存・再読込 | 元の意味を保つ本文から同じ参照関係を復元 |

## 実装計画で決める事項

- 既存コードに合わせた部品・フック・純粋関数の配置と公開API。
- 循環を含むグラフの配置方式、既存の配置処理を利用できるか。外部ランタイム依存を原則禁止するAGENTS.mdに従い、既存処理の利用・自前実装を前提に検討する。
- ズームの範囲、実機での操作割当、狭いウインドウへの切替寸法。
- 代表的な文書規模での計測結果に基づく性能目標。

いずれも本ドラフトの機能範囲を増やす決定ではない。数値や方式を未検証のまま実装済み・保証済みと扱わない。
