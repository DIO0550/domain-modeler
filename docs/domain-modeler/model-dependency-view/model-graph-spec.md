# モデル依存図 — グラフ生成仕様（コアロジック）

機能: [概要](./index.md) / 状態: 実装前提を整理した仕様（機能は未実装）

## 責務と境界

既存 model-core のAST・参照解決結果・診断を入力として、画面に依存しないノードと参照の集合を導出する。DOM・React・Tauri・ファイルI/O・LLMへの依存は持たない。新しいパーサーやHTTP APIは作成しない。

具体的な公開API名と配置方式は実装計画で決める。外部ランタイム依存を原則禁止するAGENTS.mdに従う。本書はデータの意味と振る舞いを規定する。

## 入出力

| 区分 | 必要な情報 |
| --- | --- |
| 入力 | 文書の同一リビジョンに対応するAST、定義・参照解決結果、診断 |
| ノード | 識別子、宣言名、種類、構成要素、定義位置、関連診断 |
| 参照 | 参照元・参照先、役割、修飾、ソース位置、解決状態 |
| 描画用の辺 | 参照元と参照先の組、そこに属する参照の一覧 |
| 出力全体 | ノード、辺、図に所属させられない診断、入力リビジョン |

レイアウト座標はこの意味的なグラフとは分離する。出力を得るために元のテキストを書き換えない。

入力は[文書同期仕様の採用境界](./document-sync-spec.md#採用境界と部分ast)を通った現在の本文に対応する。「解析済み」は診断がないという意味ではない。ErrorDecl・未定義・重複診断を含む既存の解析結果をそのまま受け取り、診断なしのモデルへ変換する検証を図の前提に追加しない。

## ノード生成

| 入力宣言・項目 | 生成内容 |
| --- | --- |
| ANDのdata | RECORDノード。各項と修飾を保持 |
| ORのdata | CHOICEノード。選択肢と修飾を保持 |
| 単一参照のdata | ALIASノード。対象と修飾を保持 |
| 制約付きdata | VALUEノード。型と制約を保持 |
| workflow | WORKFLOWノード。input / output / errorを個別に保持 |
| プリミティブ参照 | ノードを作らず、参照元の項目として保持 |
| 未定義の非プリミティブ参照 | 同じ名前について1つの未定義ノードを作る |
| state-machine | 依存図の通常ノードを作らない |
| 構文エラー宣言 | 正常な宣言ノードを捏造せず、既存診断を出力に残す |

未定義ノードの識別子空間は宣言ノードと分ける。文書中の名前からHTMLやコードを生成して実行しない。画面ではテキストとして扱う。

## 参照の意味

| 宣言内の位置 | 関係の役割 | 方向 |
| --- | --- | --- |
| dataのAND項 | 構成要素 | 宣言 → 項が参照する宣言 |
| dataのOR項 | 選択肢 | 宣言 → 項が参照する宣言 |
| dataの単一参照 | 別名 | 宣言 → 参照先 |
| workflowのinput | 入力 | workflow → 参照先 |
| workflowのoutput | 出力 | workflow → 参照先 |
| workflowのerror | エラー | workflow → 参照先 |

矢印は構文上の参照を意味する。入力データがworkflowに流入する方向を描いたデータフロー図ではない。ORを継承、ANDを所有・ライフサイクルの拘束へ変換しない。

`list`・`option` は各参照に属する。`list option` のような重なりを単一の多重度へ丸めない。元の修飾と順序を保持して表示する。

## 辺の集約

- 元の参照は出現箇所ごとに保持する。
- 描画用の辺だけを「参照元ノード・参照先ノード」の組で集約する。
- 同じ型をinputとoutputの両方で使う場合、1本の辺に両方の役割を持たせる。
- インスペクターでは、役割・修飾・位置ごとに各参照を確認できる。
- 集約しても警告やジャンプ先を1件に潰さない。
- ノードと参照の既定順序はソースの出現順とし、同じ入力の出力順を安定させる。

## 参照解決との整合

- 宣言順にかかわらず、既存の全文参照解決結果を使う。
- 同名宣言の扱いは既存仕様に従い、最初の宣言を参照先にする。後続の重複宣言も別ノードとして表示し、重複診断を付ける。
- 同名宣言のノードIDを名前だけで作らず、同一解析結果内で一意にする。重複ノードのラベルに宣言行を添え、区別できるようにする。
- 既存の参照解決がworkflowを参照先として返した場合は、そのノードへの参照として表示する。依存図だけで型チェック規則を追加しない。
- state-machine等の表示対象外宣言へ解決された参照は、未定義と誤表示しない。「図の対象外」として元の項目に残し、定義位置へ移動できるようにする。通常の辺は作らない。
- state-machineのイベント名は型参照ではない。名前がdataと一致しても辺を作らない。

## 異常・特殊ケース

| ケース | 振る舞い |
| --- | --- |
| 未定義参照 | 未定義ノードへ接続し、既存の警告を対応する参照に保持 |
| 定義が後から追加 | 未定義ノードを除去し、通常の宣言ノードへ接続 |
| 定義が削除 | 参照が残れば未定義ノードへ変化 |
| 自己参照 | 自己ループを保持する |
| 相互・多段の循環 | 全ノードと辺を保持する。再帰処理で無限ループしない |
| 重複参照 | 出現箇所を保持し、辺だけ集約 |
| 一部の構文破損 | 正常に解析された宣言のグラフ生成を継続 |
| 孤立宣言 | 辺がなくても表示対象に含める |

循環の有無は表示処理の停止条件にしない。[整合性規約](../../../rules/consistency.md)の循環禁止はモジュールのimport依存に適用する。現行の型参照解決に循環診断はなく、図側でも新しい診断や保存拒否を追加しない。その他の既存診断は保持する。確認したコードと後続実装の前提は[概要の照合記録](./index.md#既存動作との照合記録)を参照。

## 直接近傍の抽出

選択ノードと、それが始点または終点である辺のもう一端を集合に含める。辺は選択ノードに接続するものだけを返す。自己ループでノードが重複せず、循環でも1段だけで停止する。

未定義ノードも選択可能とし、その直接の参照元を返す。図の対象外宣言は直接近傍のノードには含めず、インスペクターの参照項目として維持する。

## 配置に渡す情報

- ノードID、描画用の辺、UIが計測したノード寸法を配置処理へ渡す。
- 配置処理は循環・自己ループ・複数の非連結成分を扱えること。
- 同じ入力・寸法なら再配置結果を安定させる。
- 意味的なグラフのためにノードを追加・削除しない。辺をまとめる場合も参照情報を失わない。

## 受入用の最小サンプル

```text
data 注文ID = string
data 顧客情報 = string
data 商品ID = string
data 数量 = int constrained 1..100
data 注文明細 = 商品ID AND 数量
data 注文 = 注文ID AND 顧客情報 AND 注文明細 list
data 注文確定 = 注文ID
data 検証エラー = string

workflow 注文を確定する =
  input: 注文
  output: 注文確定
  error: 検証エラー
```

期待結果: 宣言ノード9個、描画用の辺9本、未定義ノード0個。注文を中心とした直接近傍は、注文・注文ID・顧客情報・注文明細・注文を確定するの5ノードと、注文に接続する4本の辺。商品IDや数量は2段先のため含まない。

## 受入条件

| ID | 入力・条件 | 期待結果 |
| --- | --- | --- |
| CORE-01 | 上記サンプル | ノード・辺・近傍の集合が期待結果と一致 |
| CORE-02 | 同じ型をworkflowのinput/outputに指定 | 1本の辺に両役割・両位置を保持 |
| CORE-03 | ORとlist optionを含む | 継承と解釈せず、結合と修飾の意味を保持 |
| CORE-04 | 後方にある定義を参照 | 正常な辺となり、未定義ノードを作らない |
| CORE-05 | 未定義の型を複数箇所から参照 | 補助ノードは1つ、参照箇所は全て保持 |
| CORE-06 | 循環と自己参照 | 全辺を保持して処理が終了 |
| CORE-07 | 重複名の宣言 | 先頭への参照と後続の診断を保持 |
| CORE-08 | state-machineイベントとdataが同名 | イベント由来の辺を作らない |
| CORE-09 | 対象外宣言への解決済み参照 | 未定義と混同せず、参照位置を保持 |
| CORE-10 | 構文エラーの後に正常な宣言 | 正常な宣言の図が失われない |
