## 1. 技術スタック

| 領域 | 採用 |
| --- | --- |
| シェル | Tauri v2(macOS を主対象) |
| フロントエンド | React + TypeScript + Vite |
| パッケージ管理 | pnpm |
| テスト | Vitest(TypeScript)、Rust 標準テスト(Rust) |

### 1.1 依存方針

- **coreパッケージは依存ゼロ**(TypeScript 標準ライブラリのみ)
- UIパッケージの依存は React 本体のみを基本とし、キャンバス・エディタ・ハイライトはすべて自前実装(既定義: ReactFlow / CodeMirror 等は採用しない)
- Rust側は Tauri 公式プラグインを優先し、サードパーティ crate は最小限(ファイル監視の定番 crate は許容)
- ファイル監視は `notify` crate(6.1 系)を使う。OS の FS イベントを扱う定番実装で、公式プラグインに「パスを監視して change/delete を返す」薄い IPC は無い。`notify` 8 系は Rust 1.85 を要求するため、現行の rust-version(1.77) に合う 6.1 を採用する
- 新規依存の追加は理由を仕様書に残す

## 2. パッケージ構成

pnpm workspace のモノレポとする:

```
domain-modeler/
├── packages/
│   ├── canvas-core/   # canvas-core.md(依存ゼロ)
│   └── model-core/    # model-core.md(依存ゼロ)
├── apps/
│   └── desktop/       # Tauri アプリ(React UI + Rust)
└── docs/              # 仕様書
```

- 依存方向は apps → packages の一方向。core 同士は互いに依存しない
- core をパッケージとして分離するのは、UI → core の一方向依存を構成レベルで強制するため
- 各パッケージの公開APIは単一の入口に集約する

## 3. Rust層とIPC

Rust層は薄く保ち、ドメインロジックを持たない。フロントエンドへ提供する操作:

| 操作 | 内容 |
| --- | --- |
| ファイル読み込み | パスを受けて内容を返す |
| アトミック書き込み | 同一ディレクトリの一時ファイルに書いてからリネームで置き換える(書きかけのファイルを外部に見せない) |
| 保存ダイアログ / オープンダイアログ | 拡張子フィルタ付き |
| ファイル監視の開始・停止 | 対象パスの変更・削除イベントをフロントエンドへ通知する |
| アプリ設定の読み書き | 6 参照 |

- 判断(取り込むか・警告を出すか等)はすべてフロントエンド側で行う。Rustはイベントを運ぶだけ

## 4. 自動保存

- 文書の変更からデバウンスして書き込む: 変更後 500ms 無操作で保存。連続変更中も最大 2秒 ごとには保存する(取りこぼし防止の上限)
- トランザクション中(ドラッグ中・テキスト編集セッション中)は確定を待つ
- 書き込みは常にアトミック書き込みを用いる
- アプリ終了・タブを閉じる際は即時保存してから閉じる

## 5. ファイル監視と外部変更の取り込み

canvas-core 10 / model-editor 7 の取り込みを支える機構:

- 開いている文書のファイルを監視する
- **自己書き込みの判別**: 直近に自分が書き込んだ内容のハッシュを保持し、変更イベントで読んだ内容が一致すれば自分の保存によるイベントとして無視する
- 変更イベントはデバウンス(200ms)してから読み込む(外部エディタの連続書き込み対策)
- Rust は対象パスの親ディレクトリを監視し、200ms 無イベントのあとファイルの有無で `changed` / `deleted` をフロントエンドへ送る。読み込み・自己書き込み判別・取り込み判断はフロントエンド
- IPC: `start_file_watch` / `stop_file_watch`(失敗も値として返す)。イベント名は `file-watch`
- 読み込んだ内容の検証と取り込みは各 core、成否の通知は app-shell 5.2 の規則に従う
- 削除イベントは app-shell 5.1 の欠損状態へ遷移させる(監視は継続し、ファイルが再出現したら外部変更として扱う)

### 5.1 競合の整理

自動保存(書く)と監視(読む)が同じファイルに対して動くが、以下により安全とする:

1. 書き込みはアトミックなので、監視側が書きかけを読むことはない
2. 自己書き込みはハッシュ判別で取り込み対象から外れる
3. 外部変更とアプリ操作が重なった場合は「後勝ち」(canvas-core 10)。最後に保存した内容がファイルに残り、取り込みは履歴に積まれているため undo で救済できる

## 6. アプリ設定

- OS標準のアプリ設定ディレクトリに JSON(`settings.json`)で保存する(文書ファイルには含めない)
- 内容: 開いていたタブ群とアクティブタブ(app-shell 2.1)、ウィンドウ位置・サイズ、テーマ設定
- 設定ファイルが壊れていても起動は失敗させない(既定値で起動する)
- IPC: `read_app_settings` / `write_app_settings`。読み込み失敗・壊れた JSON は既定値を返す。書き込み失敗は値として返す
- 書き込みはアトミック書き込みを用いる

## 7. エラーハンドリングの方針

- ファイルI/Oの失敗(権限・ディスク等)はトーストで通知し、アプリは落とさない
- 自動保存の失敗は再試行し、失敗が続く場合は警告状態(app-shell 5.1 に準じたバナー)で知らせる
- core の検証エラー・パースエラーは各仕様書の規則に従う(基盤としては「例外で落とさず値として返す」ことのみ規定する)

## 8. テスト方針

- core 2パッケージ: Vitest(各仕様書のテスト方針に従う)
- UI: コンポーネントの結合テストは最小限とし、core のカバレッジを厚くする方針
- Rust: アトミック書き込み・監視イベント・アプリ設定読み書きの単体テスト
- E2E(アプリ全体の自動操作)は初期スコープ外

## 9. スコープ外

- 自動アップデート、テレメトリ
