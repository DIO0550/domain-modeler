## 1. 責務と非責務

### 責務

- ウィンドウとタブ: 複数文書の管理、タブ状態の復元
- ファイルの入口: 新規作成・開く(メニュー / ドラッグ&ドロップ / OSの関連付け)
- 通知: 外部変更・エラーのユーザーへの提示
- スキャフォールド生成の起動と確認画面(規則は scaffold.md)

### 非責務

- 各画面の中身(canvas-ui / model-editor)
- 保存・ファイル監視・自己書き込み判別(technical.md)

## 2. ウィンドウとタブ

- 1ウィンドウ・タブ型。タブ1つ = 文書1つ(`.dcanvas` または `.dmodel`)
- タブには文書種別のアイコンとファイル名を表示する。同名ファイルが複数開かれた場合は区別に必要な範囲で親ディレクトリ名を添える
- 同じファイルを二重に開こうとした場合は既存タブをアクティブにする(二重に開かない)
- 保存ボタン・未保存マークは存在しない(常時自動保存)。控えめな「保存済み」インジケータのみ表示する

### 2.1 起動時の復元

- 前回終了時に開いていたタブ群とアクティブタブを復元する
- タブ状態はアプリ設定として保存する(文書ファイルには含めない。保存先は technical.md)
- 復元時にファイルが存在しない場合は 5.1 の欠損状態としてタブを開く

## 3. 新規作成

- 新規作成時は種別(キャンバス / ドメインモデル)を選び、**即座に保存ダイアログで保存先を決める**
- ファイルが作られてからタブが開く。「無題」文書は存在しない — すべての文書は常にファイルの実体を持ち、自動保存・ファイル監視・AI共同作業の前提が最初から成立する
- 初期内容: キャンバスは空(付箋・接続なし、ビューポート原点)、モデルは空テキスト

## 4. ファイルを開く

| 手段 | 挙動 |
| --- | --- |
| メニュー(開く) | 拡張子フィルタ付きダイアログ |
| ドラッグ&ドロップ | ウィンドウへの `.dcanvas` / `.dmodel` のドロップで開く。複数ファイル可 |
| OSの関連付け | `.dcanvas` / `.dmodel` をアプリに関連付け、Finder のダブルクリックで起動・オープンする |

- 対応外の拡張子は通知を出して無視する
- 読み込みで検証エラー(canvas-format 8 / パース不能なJSON)の場合、タブは開かずエラー内容を通知する。`.dmodel` はどんな内容でも開ける(パースエラーは model-editor 内の表示で扱う)

## 5. 例外状態の扱い

### 5.1 ファイルの欠損(外部での削除・リネーム)

- タブは閉じず、警告状態(タブ上の警告アイコン + 画面内バナー)で残す
- メモリ上の文書はそのまま編集を続けられる。次の自動保存で同じパスにファイルが再作成され、警告は解除される
- リネームだった場合はユーザーが新しいパスのファイルを開き直す(追跡はしない)

### 5.2 外部変更の取り込み通知

方針: 正常系は静かに、異常系ははっきりと。

| 状況 | 通知 |
| --- | --- |
| アクティブタブへの取り込み成功 | 通知なし(画面の変化そのものが通知。undo で戻せる) |
| 背景タブへの取り込み成功 | タブに変更マーク(ドット)。タブを開いたら消える |
| 取り込み失敗(検証エラーで無視) | トースト表示。ファイルと画面が食い違っている異常状態のため明示的に知らせる |

## 6. メニュー構成(最小)

- アプリ: 設定(テーマ等。項目は実装時に確定)・終了
- ファイル: 新規(キャンバス / モデル)・開く・タブを閉じる
- 編集: undo / redo・カット / コピー / ペースト(OS標準)
- 生成: キャンバスからドメインモデルを生成(アクティブタブがキャンバスのときのみ有効。scaffold.md 6)

## 7. スコープ外

- 複数ウィンドウ、タブの分割表示(キャンバスとモデルを並べて見る等)
- 最近開いたファイルの一覧
- タブのピン留め・並べ替えの永続化(並べ替え自体は可、順序は復元対象)
- 自動アップデート・クラッシュレポート
