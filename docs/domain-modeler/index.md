# domain-modeler 仕様書

ドメイン駆動設計のための個人用デスクトップアプリ。イベントストーミングのキャンバスと、『関数型ドメインモデリング』(Scott Wlaschin)風のテキストDSLエディタの2機能を持つ。

## 1. コンセプト

- **発散 → 収束**: キャンバスで付箋を出し(発散)、ドメインモデルDSLで型として定義する(収束)。2つは同一アプリ内の独立した機能で、画面もドキュメントも別
- **ファイルが唯一の真実**: ローカルファイル(`.dcanvas` / `.dmodel`)に常時自動保存。AIエージェント(Claude Code等)や外部エディタが同じファイルを直接編集する共同作業を正式にサポートする(監視・取り込み・undoによる救済)
- **一方向の橋**: キャンバス → `.dmodel` のスキャフォールド生成(一度きり)。双方向同期はしない
- **依存最小・自前実装**: キャンバスもDSLパーサーもエディタも自前。coreは依存ゼロのheadlessパッケージとしてUIから分離する

## 3. ロードマップ

ファイル形式は最初から全機能を受け入れる(形式にPhaseの概念はない)。Phaseは実装の提供順のみを定める。

### Phase 1: キャンバス基礎

- 付箋のCRUD・自由配置・リサイズ・前面化(種別は Big Picture 最小セット: Event / Actor / External System)
- パン・ズーム、undo / redo
- 自動保存・ファイル監視・外部変更の取り込み(AI共同作業はこの時点から成立させる)
- app-shell: タブ・新規作成・開く・復元

### Phase 2: 接続とフルセット

- 接続線(作成・ラベル・アンカー明示指定)
- 付箋種別の全8種化(+ Command / Policy / Aggregate / Read Model / Hotspot)
- 接続ルールのソフト警告

### Phase 3: ドメインモデルエディタ

- DSLパーサー(model-core)一式
- split-viewエディタ(ハイライト・プレビューカード・警告表示)
- 編集支援(ジャンプ・スタブ生成・リネーム・雛形挿入)

### Phase 4: スキャフォールド生成

- キャンバス → `.dmodel` 変換・確認画面・新タブで開く

## 4. 主要な設計判断の記録

| 判断 | 選択 | 主な理由 |
| --- | --- | --- |
| キャンバスの配置モデル | 自由配置(座標保存) | 発散フェーズを重視。構造化はDSL側が担う |
| キャンバス実装 | 自前(ReactFlow不採用) | 依存最小。難所は座標変換とズーム不動点のみ |
| キャンバス保存形式 | JSON + 派生note | 座標が主データ。可読性はnoteで補い、真実はID参照 |
| DSL保存形式 | プレーンテキスト | 本の書き味。AIが最も自然に編集できる |
| 2機能の関係 | 独立 + 一方向生成 | 双方向同期の複雑さを回避 |
| AI共同作業 | ファイル監視 + 後勝ち + 履歴 | file as truth と整合。マージ・MCPより軽い |
| undo方式 | スナップショット | イミュータブル設計なら参照コピーで済む |
| 接続ルール | ソフト警告 | ブレストを妨げず、定石は教える |
