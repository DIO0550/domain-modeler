# canvas-format — `.dcanvas` ファイル形式定義

| 項目 | 内容 |
| --- | --- |
| 対象 | `.dcanvas`(イベントストーミングキャンバス文書) |
| 分類 | DB(永続化形式) |
| ステータス | Draft |
| 関連文書 | canvas-core.md / canvas-ui.md(線の描画規則・種別の色)/ model-format.md / technical.md(自動保存・アトミック書き込み) |

---

## 1. 基本原則

- 1文書 = 1ファイル。外部データベース・sidecar を持たない自己完結形式とする
- 表現は JSON。文字エンコーディングは UTF-8(BOMなし)、改行は LF
- ファイルの読み書き手順(自動保存・アトミック書き込み)は technical.md で定義する。本書は形式のみを規定する

## 2. トップレベル

```json
{
  "version": "1.0",
  "title": "注文ドメイン",
  "viewport": { "x": 0, "y": 0, "zoom": 1 },
  "stickies": [],
  "connections": []
}
```

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `version` | string | ✓ | スキーマバージョン。`<major>.<minor>` 形式。現行は `"1.0"` |
| `title` | string | ✓ | 文書タイトル。空文字可 |
| `viewport` | Viewport | ✓ | 前回終了時の表示位置。開いた際に復元する |
| `stickies` | Sticky[] | ✓ | 付箋の配列。空配列可 |
| `connections` | Connection[] | ✓ | 接続線の配列。空配列可 |

未知のトップレベルフィールドを含むファイルは、読み込み時にエラーとせず該当フィールドを無視する(前方互換のための余地)。ただし書き戻し時に未知フィールドは保持しない。

### 2.1 バージョンの意味論

- **major**: 破壊的変更(既存フィールドの意味・型・必須性の変更、削除)で増える
- **minor**: 追加のみの変更(フィールド・列挙値の追加)で増える
- number型ではなくstring型とする。JSONのnumberでは `1.0` がパース→再保存で `1` に正規化され、マイナーが失われるため

読み込み時の判定:

| 条件 | 挙動 |
| --- | --- |
| majorが一致 かつ minorが既知以下 | 通常読み込み |
| majorが一致 かつ minorが既知より上 | 読み込む(未知フィールドは無視)。保存すると未知フィールドが失われる旨を警告する |
| majorが不一致 | エラー(読み込まない) |

保存時は常にアプリが対応する最新バージョンで書き込む。

## 3. Viewport

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `x` | number | ✓ | ワールド座標系でのパンオフセットX |
| `y` | number | ✓ | ワールド座標系でのパンオフセットY |
| `zoom` | number | ✓ | ズーム倍率。有効範囲 `0.1`〜`4.0` |

読み込み時に `zoom` が有効範囲外の場合は範囲内にクランプする。

## 4. Sticky(付箋)

```json
{
  "id": "stk_x7f3q9",
  "type": "event",
  "text": "注文が確定した",
  "position": { "x": 320, "y": 180 },
  "size": { "width": 160, "height": 100 }
}
```

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✓ | 文書内で一意。形式は 6 参照 |
| `type` | string | ✓ | 付箋種別。列挙は 7 参照 |
| `text` | string | ✓ | 付箋本文。空文字可。改行可 |
| `position` | Point | ✓ | ワールド座標での左上位置 |
| `size` | Size | ✓ | 付箋の幅・高さ(ワールド座標系、ズーム非依存) |

- `size` は必須とする。省略時デフォルトは設けない(パース分岐を増やさないため)。新規作成時に種別ごとの標準サイズを書き込む
- 座標・サイズは number(小数可)。負の座標を許容する(キャンバスは無限)

| Point | 型 | Size | 型 |
| --- | --- | --- | --- |
| `x` | number | `width` | number(> 0) |
| `y` | number | `height` | number(> 0) |

## 5. Connection(接続線)

```json
{
  "id": "con_a1b2c3",
  "from": "stk_x7f3q9",
  "to": "stk_9k2m4p",
  "fromAnchor": "bottom",
  "label": "在庫確認後",
  "note": "注文を確定する -> 注文が保留された"
}
```

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✓ | 文書内で一意 |
| `from` | string | ✓ | 始点付箋の `id`。矢印の根本 |
| `to` | string | ✓ | 終点付箋の `id`。矢印の先端 |
| `fromAnchor` | string | — | 始点アンカー。`top` / `right` / `bottom` / `left`。省略時は自動計算 |
| `toAnchor` | string | — | 終点アンカー。値・規則は `fromAnchor` と同じ |
| `label` | string | ✓ | 自由記述ラベル。空文字可 |
| `note` | string | ✓ | 派生フィールド。`<始点付箋テキスト> -> <終点付箋テキスト>` 形式の可読スナップショット |

- 有向。種別間の接続ルールはファイル形式としては検証せず、どの組み合わせも保存可能とする。推奨ルール外の接続はUI上で警告表示する(ソフト警告)。ルール表と判定は canvas-core.md、表示は canvas-ui.md で定義する
- `from === to`(自己参照)は不正とする
- 同一ペア間の複数接続は許容する

### 5.1 アンカー

- アンカーは付箋の四辺のいずれかを指す。辺上の位置指定(割合等)はスコープ外
- `fromAnchor` / `toAnchor` は省略可能。省略 = 自動(2枚の付箋の相対位置から最寄りの辺を描画時に毎回計算する)。ユーザーが明示的に辺を選んだ接続のみ値を保存する
- 自動計算の具体規則、線の形状(直線 / ベジェ)、ラベル配置は描画時の導出でありファイルには保存しない。規則は canvas-ui.md で定義する

### 5.2 note(派生フィールド)

- 人間・AIがファイルを直接読んだ際に接続を判読できるようにするための冗長フィールド。真実は `from` / `to` のID参照であり、`note` は保存のたびにアプリが付箋テキストから再生成する
- 読み込み時は完全に無視する。手動で書き換えても動作に影響しない
- 各付箋テキストは先頭20文字で切り、改行はスペースに置換する

## 6. ID形式

- `crypto.randomUUID()` の先頭12桁(ハイフン除去後)に種別プレフィックスを付与する
- 付箋: `stk_` + 12桁、接続線: `con_` + 12桁
- IDはファイル内でのみ意味を持つ。ファイル間参照には使用しない

## 7. 付箋種別の列挙

| 値 | 表示名 |
| --- | --- |
| `event` | Domain Event |
| `actor` | Actor |
| `command` | Command |
| `policy` | Policy |
| `aggregate` | Aggregate |
| `readModel` | Read Model |
| `externalSystem` | External System |
| `hotspot` | Hotspot |

種別ごとの色・標準サイズは canvas-ui.md で定義する(形式仕様には含めない)。どの種別をUIのどの段階で提供するかはロードマップの関心事であり、形式は最初から全種別を受け入れる。

## 8. 検証ルール

読み込み時に以下を検証し、違反はエラーとして扱う(エラー時のUI挙動は app-shell.md 参照):

1. `version` が `<major>.<minor>` 形式であり、majorがアプリの対応majorと一致すること(minorの扱いは 2.1 参照)
2. `stickies[].id` / `connections[].id` が文書内で一意であること
3. `connections[].from` / `to` が存在する付箋を参照していること
4. `type` が既知の列挙値であること
5. `size.width` / `size.height` が正の数であること
6. `fromAnchor` / `toAnchor` が存在する場合、既知の値(`top` / `right` / `bottom` / `left`)であること

`note` は検証対象外(読み込み時に無視し、保存時に再生成するため)。

## 9. スコープ外

- 画像等のバイナリ資産の埋め込み、レイヤー、付箋のグループ枠(Bounded Context囲いは将来検討)
- `.dmodel` とのID相互参照(スキャフォールド生成は一方向・名前ベースであり、リンクを持たない)
