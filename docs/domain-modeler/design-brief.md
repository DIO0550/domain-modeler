# domain-modeler デザインブリーフ

UIデザイン検討用の自己完結した説明資料。仕様の正規版は各仕様書(canvas-ui.md / model-editor.md ほか)にあり、本書はデザインツールに渡すための要約である。

---

## 1. プロダクト概要

**domain-modeler** は、ドメイン駆動設計のための個人用デスクトップアプリ(macOS / Tauri)。2つの独立した編集画面を持つ:

1. **キャンバス**: イベントストーミング(付箋を自由に貼って矢印で繋ぐブレスト手法)のデジタル版
2. **モデルエディタ**: 『関数型ドメインモデリング』(Scott Wlaschin)風のテキストDSLで型とワークフローを書く

思想: 発散(キャンバスで付箋を出す)→ 収束(DSLで型として定義する)。ローカルファイルが唯一の真実で、AIエージェントが同じファイルを直接編集して共同作業する。

デザインの方向性キーワード: 道具感、静かで邪魔しない、物理の付箋の気持ちよさ、テキストエディタの端正さ。装飾より情報の可読性。ライト / ダーク両テーマ想定。

## 2. アプリ全体(シェル)

- 1ウィンドウ・タブ型。複数の文書(キャンバス文書 / モデル文書)をタブで開く
- タブには文書種別がわかる小さなアイコン + ファイル名
- 保存ボタンはない(常時自動保存)。「保存済み」を示す控えめなインジケータのみ
- 外部(AI)がファイルを変更したときのトースト通知がある

## 3. 画面A: キャンバス

### レイアウト

- 上部バー: 付箋種別パレット(8種) + undo / redo
- 残り全面が無限キャンバス。スクロールバーなし、パン・ズームで移動

### 付箋(8種)

物理付箋の色慣習に従う。角丸の矩形、中央に本文、左上に小さく種別キャプション。

| 種別 | 色系統 | サイズ感 |
| --- | --- | --- |
| Domain Event | オレンジ | 標準(160×100) |
| Command | 青 | 標準 |
| Actor | 黄 | 小さめ(120×80) |
| Aggregate | 黄 | 大きめ(200×140) |
| Policy | 紫 | 標準 |
| Read Model | 緑 | 標準 |
| External System | ピンク | 標準 |
| Hotspot | 赤 | やや小さめ、僅かに傾いて表示(疑問マーカー) |

状態: 通常 / ホバー(接続ハンドルが外周に出る)/ 選択(選択枠 + 四隅リサイズハンドル + 種別変更ミニツールバー)/ 本文編集中(インライン編集)。

### 接続線

- 有向の矢印。水平に結べるときは直線、それ以外は緩いベジェ曲線
- 線の中点にラベル(背景チップ付きで線の上でも読める)。ラベルなしも多い
- **警告状態**: イベントストーミングの定石から外れた繋ぎ方(例: Actor→Event)は点線 + 警告色。ホバーでツールチップ「Policy から繋げるのは Command です」のような教育的メッセージ。操作は妨げない
- 接続選択時: 端点ハンドル表示。端点を付箋の辺へドラッグするとその辺に固定できる

### 操作の質感

- パレットで種別選択 → クリックで作成 → 即テキスト入力、のテンポ重視
- ドラッグで持ち上げると最前面に来る(物理付箋の再現)
- ピンチ / Cmd+ホイールでカーソル中心ズーム

## 4. 画面B: モデルエディタ

### レイアウト

左右分割(境界ドラッグで比率調整可)。左: テキストエディタ、右: 構造化プレビュー。常に両方表示。

### 左: テキストエディタ

等幅フォント。DSLの例:

```
// 注文ドメイン
data 注文 = 未検証の注文 OR 検証済みの注文

data 検証済みの注文 =
  注文ID
  AND 顧客情報
  AND 注文明細 list

data 注文数量 = int constrained 1..100

workflow 注文を確定する =
  input: 未検証の注文 AND 在庫状況
  output: 注文確定イベント OR 注文保留イベント
  error: 検証エラー
```

- ハイライト: 予約語(data / workflow / AND / OR / input: 等)は強調色、プリミティブ型(string / int 等)と修飾(list / option)は別系統の色、コメントは抑制色
- 未定義の型参照には点線下線(警告。エラーではない)
- パースエラー行は行背景を警告色に + 行末にメッセージ

### 右: 構造化プレビュー

宣言ごとのカードを縦に並べる。4 + 1種:

- **CHOICE カード**(OR型): ケースをピル(丸タグ)で横並び、間に "or"
- **RECORD カード**(AND型): フィールドを罫線区切りの縦リスト
- **ALIAS カード**(単一参照): 参照先を1行
- **VALUE カード**(制約付き): `int 1..100` のような型 + 制約表示
- **WORKFLOW カード**: IN / OUT / ERR の3行構造(アイコン付き)

共通: 未定義参照は点線下線 + 「未定義」バッジ。壊れた宣言はエラープレースホルダ(行番号 + メッセージ)がカードの位置に出る。

### プレビューからの操作(重要な体験)

プレビューは読むだけでなく編集の入口:

- カード内の型参照クリック → 左エディタの定義行へジャンプ
- 「未定義」バッジクリック → 末尾にスタブ(`data 検証エラー = string // TODO 詳細化`)を追記してジャンプ
- カード名からリネーム → 全参照を一括置換
- ツールバーから data / workflow の雛形挿入

「書く → 構造が絵になる → 未定義の語が次に書くものとして浮かぶ → クリックで書き始める」のループがこの画面の核。

## 5. デザインで特に検討してほしい点

1. キャンバスとモデルエディタ、性格の違う2画面をひとつのアプリとして統一感を持たせる方法
2. 付箋8色がライト / ダーク両テーマで成立する色設計(色だけに頼らない識別も)
3. 警告(点線・バッジ・ツールチップ)の「気づくが邪魔しない」トーン
4. プレビューカードのタイポグラフィ(日本語識別子 + 英語キーワード混在の可読性)
5. タブバー・パレット・ツールバーなどクローム部分の最小化(キャンバスを最大化する)
