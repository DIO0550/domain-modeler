# model-editor — ドメインモデルエディタ画面

| 項目 | 内容 |
| --- | --- |
| 対象 | `.dmodel` の編集画面(テキストエディタ + 構造化プレビュー) |
| 分類 | FE(UI層) |
| ステータス | Draft |
| 関連文書 | model-format.md(構文)/ model-core.md(パーサー・AST・警告)/ app-shell.md(タブ・通知)/ technical.md(自動保存・ファイル監視) |

---

## 1. 責務と非責務

### 責務

- テキスト編集: `.dmodel` のプレーンテキスト編集とシンタックスハイライト
- 構造化プレビュー: パース結果(AST)のカード描画
- 警告・エラーの可視化: パースエラーと未定義参照の表示
- 編集支援: プレビュー側からの操作によるテキストへの反映(ジャンプ・スタブ生成・リネーム・雛形挿入)

### 非責務

- 字句解析・構文解析・参照解決(model-core。エディタはトークン列とASTを受け取って描画するだけ)
- 保存・ファイル監視(technical.md。自動保存が常時働く)
- タブ・ファイルオープン・通知(app-shell)

依存方向は model-editor → model-core の一方向。エディタ側に字句解析を重複して持たない。

## 2. 画面構成

左右分割の split-view とする。

- 左: テキストエディタ。右: 構造化プレビュー
- 境界はドラッグで比率調整可。比率はセッション内でのみ保持する(ファイルには保存しない)
- プレビューのみ・エディタのみの表示切替は設けない(常に両方表示)

## 3. テキストエディタ

### 3.1 実装方式

- 依存ゼロで実現する。標準のテキスト入力領域の背後に、ハイライト済みの描画層を重ねてスクロール同期する方式(入力領域は文字色を透明化)
- 高機能エディタライブラリ(CodeMirror等)は採用しない
- テキスト自体の undo / redo は入力領域の標準機能に任せる(キャンバスのような独自履歴は持たない)

### 3.2 シンタックスハイライト

トークン情報は model-core から受け取る。色の意味付けのみ規定し、具体色はテーマの裁量とする:

| トークン | 表示 |
| --- | --- |
| 予約語(`data` `workflow` `AND` `OR` 等) | 強調色 |
| プリミティブ型・後置修飾 | 型色(予約語と別系統) |
| コメント | 抑制色 |
| 識別子・数値 | 標準色 |
| 未定義参照の識別子 | 標準色 + 警告の下線(5.2 参照) |

### 3.3 入力挙動

- Tabキーはスペース2つを挿入する(フォーカス移動しない)
- 改行時は前行のインデントを引き継ぐ
- パースは入力のたびに行う(行指向文法で軽量なため。間引きは実装の裁量)

## 4. 構造化プレビュー

パース済みの宣言を、出現順にカードとして縦に並べる。

### 4.1 dataカード

| 宣言の形 | 表示 |
| --- | --- |
| OR(直和) | 「CHOICE」ラベル + 各ケースをピル(丸タグ)で横並び。ケース間に "or" を挟む |
| AND(直積) | 「RECORD」ラベル + フィールドを罫線区切りの縦リストで表示 |
| 単一参照 | 「ALIAS」ラベル + 参照先を1行表示 |
| 制約付き | 「VALUE」ラベル + プリミティブ型と制約(例: `int 1..100`)を表示 |

- 後置修飾(`list` / `option`)は該当する項の右に小さなタグで表示する
- カード種別(CHOICE / RECORD / ALIAS / VALUE)はASTから導出する表示上の分類であり、ファイル形式には存在しない

### 4.2 workflowカード

「WORKFLOW」ラベル + 名前 + 以下の3行構造:

| 行 | 表示 |
| --- | --- |
| IN | input の型参照。AND連結は "+" で区切って1行に |
| OUT | output の型参照。OR連結は "or" で区切って1行に |
| ERR | error の型参照。省略時は行ごと非表示 |

### 4.3 共通規則

- カード内の型参照はすべてクリック可能とし、クリックでその型の定義カードへスクロールする(未定義参照はジャンプ先がないため 6.2 の動作)
- パースエラーで解釈できなかった宣言は、カードの代わりにエラープレースホルダ(行番号 + メッセージ)を同じ位置に表示する。正しく書けている他の宣言の表示は維持する

## 5. 警告・エラーの可視化

### 5.1 パースエラー

- エディタ側: 該当行の行背景を警告色にし、行末にメッセージを表示する
- プレビュー側: 4.3 のエラープレースホルダ
- パースエラーがあってもファイルはそのまま自動保存される(テキストが真実。エラー状態の保存を妨げない)

### 5.2 未定義参照(警告)

- エディタ側: 該当識別子に点線下線
- プレビュー側: 該当参照に点線下線 + 「未定義」バッジ
- model-format.md 9 のとおりエラーではなく警告。書き途中の自然な状態として穏やかに表示する

## 6. 編集支援(プレビュー側からの操作)

プレビューは読み取り専用の表示ではなく、テキストへ反映される操作の入口とする。すべての操作は「テキストの編集」として実現する(ASTを直接変更しない。テキストが唯一の真実)。

| 操作 | 入口 | 反映 |
| --- | --- | --- |
| 定義へジャンプ | カード内の型参照をクリック | エディタが該当宣言の行へスクロールし、カーソルを移動する |
| スタブ生成 | 「未定義」バッジをクリック | 文書末尾に `data <名前> = string // TODO 詳細化` を追記し、その行にジャンプする |
| リネーム | カードの名前から操作を呼び出し、新しい名前を入力 | 宣言名と全参照箇所を一括置換する。置換対象はASTのトークン位置に基づく(単純な文字列置換は行わない。コメント内の出現は置換しない) |
| 雛形挿入 | ツールバー(data雛形 / workflow雛形) | カーソル位置に雛形を挿入し、名前部分を選択状態にする |

- リネーム・スタブ生成はテキストの一括編集となるため、直後に undo で丸ごと戻せること
- スタブ生成の placeholder を `string // TODO` とするのは文法追加を避けるため。本にある「意図的に未定義とする」表現(`undefined` 相当のキーワード)を文法に足すかは将来の検討事項とする

## 7. 外部変更の取り込み

- `.dmodel` も AI・外部エディタとの共同作業の対象とする。取り込みの検知・判別は technical.md、方針は canvas-core.md 10 と同じ(後勝ち・マージなし)
- 反映時はテキスト全体を置き換える。カーソル位置は可能なら維持し、不可能なら文書先頭に戻す
- 編集中(IME変換中・選択中)の取り込みは確定まで遅延させる

## 8. スコープ外

- 入力補完のポップアップ(識別子補完・スニペット補完)
- エディタとプレビューのスクロール同期(ジャンプ操作で代替)
- コード折りたたみ、複数カーソル、正規表現検索置換、キーバインドのカスタマイズ
- プレビューの印刷・画像エクスポート
