## 1. 責務と非責務

### 責務

- ドキュメントモデル: 付箋・接続のCRUD操作と不変条件の維持
- ビューポート: パン・ズーム状態と座標変換
- ヒットテスト: ワールド座標に対する付箋・接続線の当たり判定
- 履歴: undo / redo
- 接続ルール判定: 種別間の推奨ルールに基づくソフト警告の判定
- 外部変更の取り込み: 外部(AI・エディタ)が編集したファイル内容の検証と履歴付き反映
- シリアライズ: ドキュメント ⇄ JSON文字列の変換と検証(規則は canvas-format.md に従う)

### 非責務

- DOM・描画・ポインタイベントの解釈(canvas-ui)
- ファイルI/O・自動保存のスケジューリング(technical.md、Rust層)
- 種別ごとの色・標準サイズの定義(canvas-ui。ただし新規付箋作成時にサイズを引数で受け取る)

依存方向は UI → core の一方向。core は純TypeScriptで、DOM・React・Tauri APIに依存しない。

## 2. モジュール分割

以下の関心事を独立したモジュールとして分割する(ファイル・関数の命名は実装の裁量):

- **ドキュメント**: 型定義と操作
- **ビューポート**: パン・ズーム状態と座標変換
- **ヒットテスト**: 当たり判定
- **履歴**: undo / redo
- **接続ルール**: ソフト警告の判定
- **シリアライズ**: 読み込み・検証・書き出し・note再生成

公開APIは単一の入口に集約し、UI層はそれ以外から import しない。型は canvas-format.md のスキーマと同型のドキュメント・付箋・接続・ビューポートを用いる。

## 3. 設計原則

- **イミュータブル**: すべての操作は「現在のドキュメントを受け取り、新しいドキュメントを返す」純粋な変換とし、入力を変更しない。状態の保持・購読はUI層(React)の責務
- **不変条件は操作が守る**: ID一意性、参照整合性、自己参照禁止などは操作の内部で保証し、不正な操作はエラーとする。「検証は読み込み時、維持は操作時」の分担
- **z順 = 配列順**: `stickies` 配列の順序が描画順(後方が前面)。前面化はドキュメント操作として提供する

## 4. ドキュメント操作

| 操作 | 内容 |
| --- | --- |
| 付箋の追加 | 種別・本文・位置・サイズを受け取り、ID採番して追加する。末尾(最前面)に置く |
| 付箋の本文変更 | 指定した付箋の本文を変更する |
| 付箋の移動 | 指定した付箋の位置を変更する |
| 付箋のリサイズ | 指定した付箋のサイズを変更する。width / height > 0 を強制する |
| 付箋の種別変更 | 指定した付箋の種別を変更する |
| 付箋の前面化 | 指定した付箋を配列末尾(最前面)へ移動する |
| 付箋の削除 | 付箋を削除する。参照している接続も同時に削除する(カスケード) |
| 接続の追加 | 始点・終点(・ラベル)を受け取り、ID採番して追加する。自己参照はエラー |
| 接続のラベル変更 | 指定した接続のラベルを変更する |
| 接続のアンカー指定 | 始点・終点アンカーの明示指定、および解除(自動計算に戻す) |
| 接続の削除 | 接続を削除する |
| タイトル変更 | 文書タイトルを変更する |

- ID採番は canvas-format.md 6 の規則(`crypto.randomUUID()` 先頭12桁 + プレフィックス)で core が行う
- `note` は操作時には保持しない(シリアライズ時に生成する派生値。7 参照)

## 5. ビューポートと座標変換

ワールド座標(文書に保存される論理座標)とスクリーン座標を分離し、変換は次の一組のみとする:

```
screen = world * zoom + pan
world  = (screen - pan) / zoom
```

| 機能 | 内容 |
| --- | --- |
| 座標変換 | 上式によるワールド⇄スクリーンの相互変換。点とサイズの両方に対応する |
| パン | パンオフセットの相対移動 |
| ズーム | 指定スクリーン座標を不動点としてズームする。カーソル下のワールド座標が動かないよう pan を補正する |
| クランプ | zoom を `0.1`〜`4.0` に収める(canvas-format.md 3 と同値) |

viewport の変更は履歴(undo / redo)の対象外とする。

## 6. ヒットテスト

| 対象 | 判定 |
| --- | --- |
| 付箋 | ワールド座標が付箋矩形内にあるか。複数該当時は配列後方(前面)を優先する |
| 接続線 | 線(描画が直線・ベジェいずれでも判定は始点・終点アンカー間の折れ線近似)からの距離が許容値以内か |

- 接続線の許容距離はスクリーン座標で8pxとし、core は `tolerance / zoom` でワールド座標に換算した値を受け取る
- アンカー位置の解決(明示指定 or 自動計算)は core が行い、自動計算は「2付箋の中心を結ぶ線と矩形の交差辺」を採用する。UIは描画にもこの解決結果を使う

## 7. シリアライズと note

- **読み込み**: JSON をパースし、canvas-format.md 8 の検証ルールを適用する。違反は種別付きエラーで返す。`note` と未知フィールドは無視する
- **書き出し**: 整形(インデント2)して文字列化する。このとき全接続の `note` を `<始点テキスト> -> <終点テキスト>`(各20文字で切り、改行はスペース化)で再生成する
- キーの出力順は canvas-format.md の表の順に固定する(git diff の安定化のため)

## 8. 接続ルール判定(ソフト警告)

接続1本を「問題なし / 警告」のいずれかに判定する。判定は許可リスト方式:

| from | to | 意味 |
| --- | --- | --- |
| `actor` | `command` | 人が操作する |
| `command` | `aggregate` | 集約が受ける |
| `aggregate` | `event` | 結果イベントが起きる |
| `event` | `policy` | イベントに反応する |
| `policy` | `command` | 反応が次の操作を起こす |
| `event` | `readModel` | イベントが情報を更新する |
| `readModel` | `actor` | 情報を見て判断する |
| `command` | `externalSystem` | 外部システムを呼ぶ |
| `externalSystem` | `event` | 外部からイベントが届く |

- `hotspot` が from / to のいずれかに含まれる接続は常に問題なしとする(疑問マーカーは何にでも貼れる)
- 判定は保存を妨げない。警告の表示方法は canvas-ui.md で定義する
- 付箋の種別変更・削除で判定結果は変わりうるため、UIは描画のたびに判定する(coreは結果をキャッシュしない)

## 9. 履歴(undo / redo)

- **方式はコマンド + 逆操作**: 文書を変更する操作をコマンドとして実行し、その逆操作を undo スタックへ積む。redo は取り消したコマンドを再実行する
- 履歴上限は100。超過分は古い順に破棄する
- 新しい操作を実行した時点で redo スタックは破棄する
- **トランザクション**: ドラッグ・リサイズ等の連続操作は開始〜確定で囲み、確定時に `History.execute` を1回だけ呼んで1コマンド(1履歴エントリ)として積む。History 自体に begin / commit 状態は持たない(中間の文書更新はUI側の下書きとして扱い、履歴へは積まない)。テキスト編集も編集セッション(フォーカスイン〜アウト)単位で1エントリとする
- viewport 変更・選択状態は履歴対象外(コマンド化しない)。Document に viewport が含まれていても、履歴へ載せるのは文書内容の変更コマンドのみとする
- undo / redo 後の派生状態(接続警告など)は再計算で得る
- コマンド種を追加するときは、必ず対になる逆操作を定義し、往復(実行→undo→redo)で文書が戻ることをテストする

## 10. 外部変更の取り込み(AI・エディタとの共同作業)

`.dcanvas` はアプリ専有ではなく、AIエージェント(Claude Code等)や外部エディタが直接編集する共同作業の媒体とする。ファイルが唯一の真実であり、外部変更はアプリに取り込まれる。

- **外部変更の反映**: 外部から読んだファイル内容を検証し、成功すれば現在のドキュメントを置き換える
- **外部取り込みは通常の履歴エントリとして積む**。AIの変更が意図と違えば undo で取り込み前に戻せる(戻した状態で操作すれば自動保存によりファイルも巻き戻る)
- 検証エラーのファイルは取り込まず、現在のドキュメントを維持する(エラーは呼び出し元へ返し、通知は app-shell の責務)
- トランザクション中(ドラッグ中など)の取り込みは呼び出し元が確定まで遅延させる
- 衝突解決は「後勝ち」の単純ルールとする。自動保存が常時働くためアプリ側に未保存差分はほぼ存在せず、マージは行わない
- ファイル監視・自己書き込みの判別(直近に自分が書いた内容との同一性チェック)・デバウンスは technical.md で定義する(coreの責務外)

## 11. テスト方針

- 全モジュールを Vitest の対象とする。DOM非依存なので jsdom 不要
- 検証・座標変換・ヒットテスト・ルール判定は表駆動テスト
- 書き出し→読み込みの往復同値性(note・キー順を除く構造の一致)をプロパティ的に確認する

## 12. スコープ外

- 複数選択・整列・スナップ(必要になった時点で操作関数を追加する)
- 接続線の経路探索(障害物回避ルーティング)
- ドキュメントの差分マージ(衝突は後勝ちで解決し、3-wayマージは行わない)・リアルタイム共同編集(CRDT等)
